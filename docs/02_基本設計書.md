## 1. はじめに
本書は、要件定義書の要件を実現するための、システムの構成・画面・機能・データ・外部とのやり取り・セキュリティの方式を定める。モジュール内部の処理や定数は、詳細設計書に記す。

## 2. システム構成

### 2.1 全体構成
サーバーを持たず、利用者のブラウザの中だけで動く。ファイルの読み込みから表示・出力までを、すべてブラウザ内で行う。

```
┌──────────────────────── 利用者のPC ────────────────────────┐
│                                                                │
│   ローカルのファイル ──(ドロップ／ファイル選択)──┐             │
│                                                   ▼             │
│   ┌───────────── Edge / Chrome ──────────────────────────┐   │
│   │  ShibaDiff.html（単一ファイル）                     │   │
│   │   ├ 画面（HTML／CSS）                                   │   │
│   │   ├ アプリ本体（JavaScript）                            │   │
│   │   ├ pdf.js（本体）＋ ワーカー（文書ごとに Blob URL で起動）│   │
│   │   └ 日本語CMap（Base64 で埋め込み）                     │   │
│   │                                                          │   │
│   │   localStorage：注釈・回転・設定だけを保存               │   │
│   │   CSP：外部通信・外部読み込み・eval を禁止               │   │
│   └──────────────────────────────────────────────────────┘   │
│                                                   │             │
│   出力 ◀──(ダウンロード／保存ダイアログ／印刷)──┘             │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 開発・配布の構成
```
GitHub リポジトリ
 ├ src/            機能ごとのソース（JavaScript 12ファイル、CSS、画面のHTML）
 ├ build.py        1つのHTMLにまとめるビルドスクリプト
 ├ assets/         アプリのアイコン（32・64・180・512px の PNG）
 ├ package.json    pdf.js（pdfjs-dist）の版を固定
 ├ ShibaDiff.html  ビルド結果（配布するファイル。GitHub Pages でも公開）
 ├ index.html      GitHub Pages の入口（ShibaDiff.html へ移る）
 ├ tests/          headless Chrome による自動テストと、テスト用ファイル
 ├ tools/          サンプルファイルの生成スクリプト
 └ docs/           要件定義書・基本設計書・詳細設計書
```

### 2.3 採用技術
| 区分 | 採用技術 | 理由 |
|---|---|---|
| 言語 | JavaScript（ES2020程度）、HTML、CSS | ブラウザだけで動かすため |
| PDF | pdf.js 4.10.38（legacy ビルド） | PDFの描画と文字の取り出しを自前で作るのは困難なため。legacy ビルドは古めのブラウザでも動く |
| アイコン | Lucide（lucide-static 1.81.0） | 線画で統一されたアイコンセット。必要なアイコンだけをビルド時にインライン SVG として埋め込むので、外部への通信もフォントの読み込みも要らない |
| ZIP の展開 | ブラウザ標準の DecompressionStream | docx/xlsx/pptx を外部ライブラリなしで読むため |
| 文字コード | ブラウザ標準の TextDecoder ＋ 自前の変換表 | 読み込みは標準機能、保存（Shift_JIS 等）は TextDecoder から逆引きの表を作る |
| 差分 | 自前実装（Myers 法＋patience 法） | 大きなファイルでも速く、行内差分まで細かく制御するため |
| ビルド | Python 3 | 文字列の結合だけで済み、環境を選ばないため |
| テスト | Python ＋ Playwright（headless Chrome） | 実際のブラウザで操作して確かめるため |

## 3. ソフトウェア構成

### 3.1 モジュール一覧
すべてのモジュールは1つのスクリプトとして結合され、名前空間となる定数（`TV`、`PV` など）を通して呼び合う。

| ファイル | 名前空間 | 責務 |
|---|---|---|
| util.js | （関数群） | 画面の部品（通知、処理中表示、ダイアログ）、ダウンロード、保存領域、文字の正規化 |
| settings.js | `Settings` | 設定の保持・変更の通知、設定画面、保存データの管理画面 |
| encoding.js | `Enc` | 文字コードの判定・読み込み・書き出し、改行の判定、バイナリのダンプ表示 |
| diff.js | `Diff` | 行の差分、行の対応付け、行内（文字・単語）の差分、数字の差 |
| office.js | `Zip`、`Office` | ZIPの読み込み、docx/xlsx/pptx からの文字の取り出し |
| pdf.js | `PDF` | pdf.js の起動、PDFを開く、文字の取り出し、ページの描画 |
| pages.js | `Pages` | テキストや画像を「ページ」として扱う（ページ表示・重ね合わせ用） |
| pagematch.js | `PageMatch` | ページの対応付け（挿入・削除されたページを見つけ、似ているページどうしを組にする） |
| notes.js | `Notes` | 変更点へのコメント（確認の状態・ひとこと）の保持・入力欄・CSV |
| report.js | `Report` | HTMLレポートの共通部品（ファイル情報・SHA-256・印刷用スタイル・CSP・画像の埋め込み） |
| textview.js | `TV` | テキスト比較の画面と操作 |
| pageview.js | `PV` | ページ表示・注釈の画面と操作 |
| overlay.js | `OV` | 重ね合わせ比較の画面と画素の比較 |
| folder.js | `FD` | フォルダ比較の画面と操作 |
| main.js | `App`、変数 `S` | ファイルの読み込み、ヘッダ・左右のファイル欄（開閉）、ファイル比較／フォルダ比較の切り替え、タブの切り替え、全画面表示、ドラッグ＆ドロップ（左右の読み込み先の表示）、キーボード操作、ヘルプ |

### 3.2 依存関係
```
                 main.js（App・S：読み込んだ左右の文書）
        ┌──────────┬────┴─────┬──────────┬──────────┐
     textview.js  pageview.js  overlay.js   folder.js   settings.js
        │            │           │                        ▲
        ├ diff.js    ├ pages.js ─┤                        │（全画面が設定を参照）
        │            └ pdf.js ───┘
        └ encoding.js（保存）           office.js・pdf.js・encoding.js は main.js の読み込みで使用
                                  util.js は全モジュールから使用
```
- 画面モジュール（TV・PV・OV）は、左右の文書 `S[0]`・`S[1]` を読むだけで、原則として互いを直接呼ばない
  - 例外：ページ表示（PV）は、変更箇所の枠を出すために重ね合わせ（OV）の `OV.regionsFor()` を呼ぶ（差分の計算を二重に持たないため）
  - 変更点のコメント（notes.js）、ページの対応付け（pagematch.js）、レポートの共通部品（report.js）は、3つの画面が共通で使う
- 文書が変わったときは、main.js が各画面の `invalidate()` を呼ぶ。各画面は表示されたとき（`activate()`）に作り直す

### 3.3 文書オブジェクト（左右の文書 `S[0]`・`S[1]`）
読み込んだファイルは、形式によらず同じ形の「文書オブジェクト」にする。各画面はこのオブジェクトだけを見る。

| 区分 | 内容 |
|---|---|
| ファイル情報 | 名前、大きさ、更新日時、元のバイト列、識別キー（名前＋大きさ＋更新日時） |
| 種類 | text / binary / pdf / docx / xlsx / pptx / image |
| 比較用の文字 | 行の配列。テキストはそのまま、PDF・Officeは取り出した文字、画像は空 |
| テキストの属性 | 文字コード、改行コード、改行の混在、末尾の改行の有無、英数字だけかどうか |
| 状態 | 編集済みかどうか、文字情報がない（スキャン）かどうか |
| ページ | `getPages()` でページの配列を返す。各ページは大きさと `draw(canvas, 倍率)` を持つ |

### 4.3 表示の規則
| 対象 | 規則 |
|---|---|
| 色 | 削除・変更前＝赤、追加・変更後＝青、選択中の差分＝紫の枠、無視した差（空行など）＝灰 |
| 記号 | 行頭に −（左）／＋（右）。変わった文字は、左が取り消し線、右が下線 |
| 挿入位置 | 反対側で文字が追加・削除された位置に縦線 |
| 数字 | 数字全体に印。右側に「差 / 増減率」の小さな札 |
| 重ね合わせ | 左だけ＝赤、右だけ＝青、色だけが変わった＝紫、共通＝薄い灰、変更箇所＝橙の枠と番号（確認済＝緑、要確認＝赤橙） |
| アイコン | ボタンには Lucide のアイコン（線の太さ2、文字色と同じ色）を文字の左に付ける。左右の入れ替え・差分の移動・ページ送り・拡大縮小・表示の切り替えなどはアイコンだけにし、説明を title と aria-label で付ける（aria-label を付けるのは文字のないボタンだけ。文字のあるボタンは、見えている文字が読み上げの名前になる） |
| 状態の表示 | 同一のときは緑の ✓、警告は橙の ⚠、誤りは赤い通知 |
| 狭い画面（760px 未満） | ファイル欄を縦に詰め、ツールバーは横スクロール、テキスト比較は一列表示、ページ表示は片側ずつ。ツールバーは、続きがある側の端にぼかしと矢印（‹ ›）を出す。ツールバーの中のポップアップは、横スクロールの枠に切り取られないよう画面に固定して出す |

## 5. 機能設計

### 5.1 ファイルの読み込み
```
ファイルを受け取る
 → 先頭のバイトで形式を判定（%PDF／PNG／JPEG／GIF／BMP／WebP／TIFF／ZIP／OLE）
 → 形式ごとの処理
     PDF   ：pdf.js で開く → 全ページの文字を取り出す → 文字情報の有無を判定
     ZIP   ：中のファイル名で docx/xlsx/pptx を判定 → 文字を取り出す
     画像  ：画像として読み込む（比較用の文字は空）
     その他：文字コードを判定 → テキストとして読む（判定できなければバイナリのダンプ）
 → 文書オブジェクトを作り、S[左右] に入れる
 → 各画面に「文書が変わった」ことを知らせる
 → 両方が文字情報のない画像・スキャンなら、重ね合わせ比較に切り替える
```

### 5.2 テキスト比較
```
左右の行の配列
 → 比較の条件（空白・大小・全角半角）で各行を正規化し、行ごとに番号を振る
 → 行の差分（共通の先頭・末尾を除く → 大きければ一意な行を手がかりに分割 → Myers 法）
 → 差分のまとまりの中で、似ている行どうしを対応付ける（変更行）
 → 表示用の行の並びを作る（差分のみ表示なら一致部分を省略、一列表示なら変更行を2行に展開）
 → 表示：見えている行だけを描く（折り返し表示のときは全体を描き、画面外は描画を省く）
 → 変更行は、描くときに行内差分（文字・単語）と数字の差を計算する（結果は保持して使い回す）
```

### 5.3 ページ表示・注釈
```
各文書のページの配列（PDF はページ、テキストや Office は A4 に組んだページ、画像は1ページ）
 → ページの枠を並べる（拡大率・回転に合わせた大きさ）
 → 画面に近づいたページだけを描く。離れたページは描画を捨ててメモリを空ける
 → 各ページの上に注釈用のSVGの層を重ねる。注釈はページの座標系（pt）で持つ
 → マウス操作で注釈を作る・動かす・消す → 保存領域に保存（保存しない設定ではメモリのみ）
 → 印刷：各ページを高い解像度で描き、注釈を重ねた画像を作って印刷する
```

### 5.4 重ね合わせ比較
```
左右のページを同じ幅で描く（900px〜上限。上限は解像度の設定で 軽量 1600／標準 2400／精細 4000px）
 → スキャン画像なら、初回に位置（平行移動・回転）を自動で推定し、ページの組ごとに覚える（処理を区切り、画面を固めない）
 → 明るさの画像にして比べる（スキャン画像は、はっきり濃い画素と、薄くてもインクがある画素の2段階で判定する）
 → ずれの許容量だけ、相手の画像を太らせてから比較する（小さなずれを差分にしない）
 → 左だけ濃い画素＝赤、右だけ濃い画素＝青
 → 変わった画素を16px四方のます目で数え、近います目をまとめて変更箇所の枠にする
 ※ 許容幅・ます目の大きさ・最小の画素数は、「標準で描いた場合」に対する倍率で換算し、解像度を変えても同じ実寸で判定する
```

### 5.5 フォルダ比較
```
左右のフォルダの中身（相対パス→ファイル）を集める
 → パスの和集合を作り、片側だけのものは「左のみ／右のみ」
 → 大きさが違えば「相違」
 → 大きさが同じなら、内容比較の設定に従い 4MB ずつ読み比べて「同一／相違」
 → 一覧を表示。ダブルクリックで、その組をテキスト比較（画像同士なら重ね合わせ）で開く（ファイル比較のモードに移り、「← フォルダ一覧」で戻れる）
 → 一覧は CSV（BOM 付き UTF-8）と HTML レポートに出力できる
```

### 5.4.1 ページの対応付け
```
左右の文書のページの特徴を作る
   文字のあるPDF：ページごとの行の集まり（行が少なければ2文字の組）
   スキャン（文字なし）：ページを 48×66 に縮小した濃さ（ページ数が同じなら 1対1 とみなし、作らない。その旨を右のパネルに示し、
                         「見た目で対応を調べ直す」を押したときだけ作って調べる）
 → 似ている度合い（行・2文字の組の Dice 係数／縮小画像のコサイン類似度）がしきい値を超える組だけを「同じページ」とし、
   ページの挿入・削除を許す動的計画法で、合計が最大になる並びを選ぶ
 → 組にならなかった左右のページが同じ数だけ並ぶ区間は順に組にする（内容が大きく変わったページ）
 → 重ね合わせのページ送り・一括チェック・ページ表示の連動で使う
```

### 5.6 出力
| 出力 | 方式 |
|---|---|
| ファイルの保存 | 元の文字コード・改行・BOM・末尾の改行で書き出す。Edge・Chrome は保存ダイアログ、それ以外はダウンロード |
| パッチ | git 形式の unified diff。元の改行コード・末尾改行の印・文字コードを保つ |
| HTMLレポート（テキスト比較） | 自己完結のHTML（CSP付き）。ファイル情報（SHA-256 など）、比較条件、件数、凡例、左右の表 |
| HTMLレポート（重ね合わせ比較） | ページの一覧（追加・削除を含む）、差分画像（枠と番号付き、JPEG を data URL で埋め込み）と、左右に並べた画像（変更箇所に色と枠）の一方または両方、変更箇所の位置と大きさ、比較条件、ファイル情報 |
| HTMLレポート（ページ表示・注釈） | 注釈込みのページ画像（左右の対応するページを横に並べる／1ページずつ）、注釈・付箋の内容の一覧、ファイル情報 |
| レポートの出力設定 | どのレポートも、出力の前にダイアログで並べ方・載せる内容・画質を選ぶ。設定は `doccmp:report:<種類>` に覚える |
| HTMLレポート・CSV（フォルダ比較） | 件数の集計と一覧。CSV は BOM 付き UTF-8・CRLF（Excel で開ける） |
| 注釈ファイル | JSON。左右の文書名・大きさ・回転・注釈 |
| 印刷・PDF | ブラウザの印刷機能。印刷用の画像を並べた領域だけを印刷する |

## 6. データ設計

### 6.1 主な内部データ
| データ | 内容 | 寿命 |
|---|---|---|
| 文書オブジェクト（S[0]・S[1]） | 3.3 のとおり | ファイルを閉じるまで |
| 差分の行（rows） | 左の行番号・右の行番号・種類（一致／変更／左のみ／右のみ／無視）・まとまりの番号・行内差分の結果 | 比較し直すまで |
| 差分のまとまり（blocks） | 行の範囲と、左右それぞれの行番号の範囲（コピーに使う） | 比較し直すまで |
| 元に戻す履歴 | 左右の行の配列の写し（最大200回分） | ファイルを読み込み直すまで |
| 注釈 | ページ番号ごとの注釈の配列（ペン・マーカー・枠・付箋） | 開いている間（設定でオンにしたときは保存領域） |
| 変更点のコメント | 左右のファイルの組ごとに、変更点の id → {状態, ひとこと, 記入者, 日時} | 開いている間（設定でオンにしたときは保存領域）。注釈ファイルにも入る |
| 注釈の取り消し履歴 | 変更前の注釈の写し（最大200回分） | 開いている間 |
| 位置合わせ | ページの組ごとの [X, Y, 回転] | ファイルを読み込み直すまで |
| ページの対応 | 左右のページの組 `{l, r}` の配列（片側にしかないページは反対側が -1） | ファイルを読み込み直すまで |

### 6.2 ブラウザへの保存（localStorage）
すべて `doccmp:` で始まる名前で保存する。ファイルの中身は保存しない。

| 名前 | 内容 |
|---|---|
| `doccmp:settings` | 設定（折り返し、空白表示、差分の単位、数値の差、文字の大きさ、保存するか、重ね合わせの解像度、ページの対応付け、重ね合わせの全ページ表示） |
| `doccmp:textopts` | テキスト比較の比較条件 |
| `doccmp:notes:<左のキー>\|\|<右のキー>` | 変更点のコメント（設定で自動保存をオンにしたときだけ） |
| `doccmp:report:<種類>` | レポートの出力設定（text・overlay・page・folder） |
| `doccmp:tvLayout` | 左右表示／一列表示 |
| `doccmp:pv:color`・`pv:width`・`pv:zoom` | 注釈の色・線の太さ、ページ表示の倍率 |
| `doccmp:ann:<名前>\|<大きさ>\|<更新日時>` | その文書の注釈 |
| `doccmp:rot:<名前>\|<大きさ>\|<更新日時>` | その文書の回転 |

`ann:`・`notes:`・`rot:` は、設定で自動保存をオンにしたときだけ保存する。オンからオフにするときは、保存済みのこの3種類を削除するかを確かめる。

## 8. セキュリティ設計
| 脅威 | 対策 |
|---|---|
| 文書の中身の外部への送信 | 通信を行うコードを持たない。CSP で `connect-src 'none'` などを指定し、ブラウザに通信を禁止させる |
| 文書の中身・ファイル名に仕込まれたスクリプト | 画面に出す文字はすべてエスケープする。HTMLレポートにも CSP を付ける |
| 細工したOffice文書（ZIP爆弾） | 展開後の大きさに上限を設ける（1項目 100MB、1ファイルの合計 300MB、16MB を超えたら圧縮率 200 倍まで）。ヘッダの値は偽装できるため、実際に展開したバイト数を数えて上限で中止する |
| 細工した注釈ファイル | 種類ごとに項目を検証し（色は `#` に続く16進3〜8桁の形式、座標は数値の範囲内、文字は長さの上限）、合わないものは捨てる。読み込み・保存・描画のたびに検証する |
| PDF 内の JavaScript・リンク | pdf.js では描画だけを行い、スクリプトは実行しない（`isEvalSupported: false`）。リンクは画像の一部として描くだけ |
| 外部のファイルの読み込み | CSP で、外部のスクリプト・画像・フォントの読み込みを禁止する。必要なもの（pdf.js、CMap）は HTML に埋め込む |
| 端末に残る個人情報 | 保存するのは注釈・変更点のコメント・回転・設定だけ（注釈・コメント・回転は、設定でオンにしたときだけ）。一覧・削除の画面を用意し、自動保存をオフにするときは保存済みのものを削除するかを確かめる。PDF のパスワードは伏せ字で入力し、保存しない |
| GitHub Pages での公開 | `ユーザー名.github.io` は同じユーザーの他の Pages サイトと同じオリジンのため、ブラウザに保存した注釈を他のページのスクリプトから読める。業務では、版を固定してダウンロードした HTML を使うよう README で案内する |

CSP の内容：
```
default-src 'none'; script-src 'unsafe-inline' blob:; worker-src blob:;
style-src 'unsafe-inline'; img-src data: blob:; font-src data: blob:;
connect-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none';
base-uri 'none'; form-action 'none'
```

## 9. 非機能要件の実現方式
| 要件 | 方式 |
|---|---|
| 単一HTML・オフライン | ビルドで CSS・JS・pdf.js・ワーカー・日本語CMapを1つのHTMLに埋め込む。ワーカーは埋め込んだ文字列から Blob URL を作って起動する |
| 大きなファイルの速さ | 行に番号を振って比較し、共通部分を先に除き、大きな範囲は一意な行で分割してから Myers 法を使う。画面は見えている行だけを描く（仮想スクロール） |
| PDF・画像の速さ | ページは画面に近づいたときだけ描く。重ね合わせの全ページ表示も、画面に近いページだけを今のページに近い順に1つずつ描き、遠ざかったページの描画は捨てる。重ね合わせの描画結果は12件まで保持して使い回す |
| 互換性 | pdf.js は legacy ビルドを使う。保存ダイアログが使えないブラウザではダウンロードにする |
| アクセシビリティ | ダイアログ内でのフォーカスの循環と復帰（重なったダイアログは、上を閉じたら下に戻る）、読み上げ用の名前、タブ・フォルダ一覧の矢印キー操作、色以外の手がかり、文字の大きさの設定 |

## 10. エラー処理の方針
- 読み込みに失敗したら、理由（壊れている・パスワード・未対応の形式など）と対処を日本語の通知で示し、それまでのファイルは残す
- 未対応の形式（.xdw、旧Office、TIFF）は、バイナリとして比較できる状態にしたうえで、変換の方法を案内する
- 保存で文字が失われる・形式が変わるときは、保存の前に確認する
- 予期しない例外は画面を止めず、開発者向けの記録（コンソール）に残す
