## 2. ビルド（build.py）

### 2.1 処理の流れ
1. `node_modules/pdfjs-dist/legacy/build/pdf.min.mjs` を読み込む
   - 末尾の `export{a as b,…}` を `globalThis.pdfjsLib={b:a,…}` に置き換える
   - 置き換え後、`pdfjs-ready` イベントを送る1文を足す
   - 結果を `<script type="module">` として埋め込む
2. `pdf.worker.min.mjs` を `<script type="text/plain" id="pdfjs-worker">` に埋め込む（実行時に Blob URL にして起動する）
3. `node_modules/pdfjs-dist/cmaps/` から日本語関係の CMap だけを選び、Base64 にして `<script type="application/json" id="cmaps">` に埋め込む
   - 対象：`UniJIS*`、`Adobe-Japan1-*`、`*RKSJ*`、`EUC-H/V`、`H`、`V`、`Hankaku`、`Hiragana`、`Katakana`、`Roman`、`WP-Symbol`、`78-*`、`83pv-*`、`90*`、`Add-*`、`Ext-*`、`NWP-*`、`Identity-H/V`
4. アプリのスクリプトを結合する
   - 先頭に `const APP = { version, build, lucide, pdfjs }` を足す（version は package.json、build はビルドした日付、lucide は lucide-static の版、pdfjs は pdfjs-dist の版）
   - アイコン：`body.html` とスクリプトの中の `<i data-i="名前"></i>` を、`node_modules/lucide-static/icons/名前.svg` の中身を使ったインライン SVG（`<svg class="ic" viewBox="0 0 24 24" aria-hidden="true">…</svg>`）に置き換える。使ったアイコンだけを埋め込む。ファイルがない名前があればビルドを止める
5. HTMLに組み立てる（head に CSP の meta 要素と CSS）
6. ライセンスの全文（`LICENSE`、pdf.js の `LICENSE`、`third_party/core-js-LICENSE`、lucide-static の `LICENSE`）をつなげ、`<script type="text/plain" id="licenses">` に埋め込む
7. 埋め込む文字列に `</script` や `<!--` が含まれていたら、ビルドを止める（HTMLが壊れるのを防ぐ）

### 2.2 出力
`ShibaDiff.html`（リポジトリの root、約2.5MB）。GitHub Pages では root の `index.html` からこのファイルへ移る。

## 5. 文字コード（encoding.js）

### 5.1 判定（`detect(bytes)`）
次の順に判定し、最初に当てはまったものを返す。

1. BOM：`EF BB BF` → `utf-8-bom`、`FF FE` → `utf-16le`、`FE FF` → `utf-16be`
2. 先頭 64KB に 0x00 がある場合
   - 奇数番目の 0x00 が25%を超え、偶数番目が2%未満 → `utf-16le`
   - 逆の場合 → `utf-16be`
   - それ以外 → `binary`
3. 制御文字（タブ・改行・ESC を除く 0x00–0x1F）が10%を超える → `binary`
4. `ESC $ B` または `ESC $ @` を含む → `iso-2022-jp`
5. すべて 0x80 未満 → `utf-8`（呼び出し側で「英数字のみ」として扱う）
6. UTF-8 として誤りなく読める → `utf-8`
7. 先頭 256KB を Shift_JIS と EUC-JP の両方で読み、点数の低い方
   - 点数 ＝ 置換文字（U+FFFD）の数 × 20 ＋ 半角カナの数

### 5.2 読み込み（`decode`）
- `binary`：16バイトずつの16進ダンプにする（オフセット、16進、ASCII。先頭 4MB（`DUMP_MAX`）まで）
- それ以外：TextDecoder で読む（BOM は除く）

### 5.3 書き出し（`encode(str, enc)` → `{bytes, unmapped}`）
| 文字コード | 方式 |
|---|---|
| UTF-8 / UTF-8 BOM付 | TextEncoder（BOM付は `EF BB BF` を先頭に足す） |
| UTF-16LE / BE | BOM ＋ 2バイトずつ（元のファイルに BOM がなかったときは、保存時に BOM を外す） |
| Shift_JIS | 逆引きの表で変換する。表は初回だけ作る：リード 0x81–0x9F・0xE0–0xFC、トレイル 0x40–0xFC（0x7F を除く）の全組を TextDecoder で読み、文字→バイトの表にする。半角カナ 0xA1–0xDF も含む。¥→0x5C、‾→0x7E、−→0x817C を補う |
| EUC-JP | 同様（0xA1–0xFE の組、半角カナは 0x8E＋1バイト） |
| ISO-2022-JP | EUC-JP の表を使い、`ESC $ B` ＋ 7ビット化。半角カナは全角にしてから変換する |

表にない文字は `?` にし、その数を `unmapped` で返す。

### 5.4 改行（`splitLines(text)`）
- CRLF / LF / CR の数を数え、最も多いものを改行コードとする
- 2種類以上あれば「混在」とする
- 末尾が改行で終わっていれば、末尾の空行を除き「末尾の改行あり」とする

## 6. 差分（diff.js）

### 6.1 行の差分（`seq(a, b)` → 操作の配列）
入力は、行ごとに振った番号の配列（Int32Array）。出力は `'e'`（一致）・`'d'`（削除）・`'i'`（挿入）の配列。

```
solve(範囲):
  先頭・末尾の一致する行を除く
  片側が空なら、残りをすべて削除または挿入にする
  範囲の行数の合計 > 1500 かつ 再帰の深さ < 200 なら:
    両側で1回ずつしか出てこない行を探し、最長増加部分列で順番のそろう行を選ぶ（patience 法）
    それらの行で範囲を分割し、各部分に solve を適用
  それ以外:
    Myers 法（差の上限 D = 2500）
    上限を超えたら、残りをすべて削除＋挿入にする
```

**Myers 法**：各 d の V 配列のうち必要な範囲（-d-1 〜 d+1）だけを保存し、後ろからたどって操作を復元する。必要な記憶量は D² 程度。

### 6.2 行の対応付け（`buildRows(ops, A, B, opts)`）
連続する削除・挿入を1つの差分のまとまりとし、その中で左右の行を対応付ける。

- 左右の行数が同じ、片側が空、または 行数の積 > 3600 → 順番どおりに対応付ける
- それ以外 → 似ている行どうしを対応付ける
  - 似ている度合い：空白をまとめた先頭400文字の、2文字の組の Dice 係数
  - 似ている度合いが 0.3 以上の組だけを使い、合計が最大になるよう動的計画法で選ぶ
  - 対応しなかった行は、隣どうしの「左のみ＋右のみ」を1組にまとめる

出力：
- `rows`：`{a, b, t, blk}` の配列
  - `a`・`b`：左・右の行番号（ない側は -1）
  - `t`：`e`（一致）／`c`（変更）／`d`（左のみ）／`i`（右のみ）／`w`（無視した差）
  - `blk`：差分のまとまりの番号
- `blocks`：`{r0, r1, a0, a1, b0, b1}` の配列（rows の範囲と、左右の行番号の範囲）

### 6.3 行内の差分（`chars(s1, s2, unit)`）
1. 両方の行をコードポイントの配列にする
2. `unit` が `auto` のときは、空白以外の文字のうち英数字が60%を超えれば `word`、そうでなければ `char` にする
3. 先頭・末尾の一致する部分を除く
   - `word` のときは、単語の途中で切れないよう、境界まで戻す
4. 残りが 6000 文字を超える、または両側の長さの積が 6×10⁶ を超えるときは、残り全体を変更とする
5. 比べる単位の列を作る
   - `char`：1文字ずつ
   - `word`：次の正規表現で区切る

     ```
     [A-Za-z0-9_]+ | ひらがな+ | カタカナ+ | 漢字+ | 全角英数+ | [ \t　]+ | その他1文字
     ```
6. Myers 法（差の上限 1500）
7. 結果をまとめる
   - 同じ種類の操作が続くところを1つにまとめる
   - 変更にはさまれた1文字だけの一致は、変更に含める
8. 片側だけに文字がある箇所は、反対側の同じ位置を「挿入位置」（`pa`／`pb`）として記録する
9. 数字への広げ
   - 変わった範囲が数字にかかっていたら、その数字全体まで広げる
   - 挿入位置が数字の中や端にあるときは、その数字全体を変更にする
   - 数字の判定：
     ```
     ((?<![0-9A-Za-z])[-+−])?(\d{1,3}(,\d{3})+(?!\d) | \d+)(\.\d+)?    （全角の数字・英字・カンマ・ピリオドも同じに扱う）
     ```
     3桁区切りのカンマは、後ろがちょうど3桁のときだけ数字の一部とみなす（CSV の区切りと区別するため）
     符号は、直前が英数字でないときだけ数字の一部とみなす（`2026-11-26` や `ABC-123` のハイフンを負号と誤認しない）

戻り値：`{a, b, pa, pb, A, B}`
- `a`・`b`：変わった範囲 `[開始, 終了)` の配列
- `pa`・`pb`：挿入位置
- `A`・`B`：文字の配列
- 位置はすべてコードポイント単位

### 6.4 数字の差（`numberDeltas(cd)`）
1. 左右それぞれで、変わった範囲にかかる数字を取り出す（カンマを除いて数値にする）
2. 左右の数が同じときだけ、順に対応付ける
3. 値が違うものについて、`{at: 右側の数字の終わりの位置, text: "+50,000 / +10.0%"}` を返す
   - 小数の桁は、左右の多い方に合わせる
   - 増減率は、元の値が0でないときだけ付ける

## 7. Office 文書（office.js）

### 7.1 ZIP の読み込み（`Zip.open(bytes)`）
1. 末尾の 65KB 以内から、中央ディレクトリの終わり（`0x06054b50`）を探す
2. 中央ディレクトリの各項目から、名前・圧縮方式・圧縮後の大きさ・ローカルヘッダの位置を読む
3. `read(name)`：方式0はそのまま返し、方式8は `DecompressionStream('deflate-raw')` で展開する
4. 展開後の大きさの上限（ZIP爆弾対策）
   - 1項目 100MB、1ファイル（ZIP）の合計 300MB
   - 展開後が 16MB を超えたら、圧縮後の大きさの 200 倍まで
   - 中央ディレクトリの展開後の大きさ（+24）が上限を超えていたら、展開せずに中止する
   - ヘッダの値は偽装できるため、展開は `getReader()` で少しずつ読み、実際のバイト数が上限を超えたら `cancel()` して中止する
   - 中止したときは「展開後のサイズが大きすぎるため読み込みを中止しました」と表示する
5. ZIP64 には対応しない

### 7.2 docx
- 本文（`word/document.xml` の body）を順にたどる
  - 段落（`w:p`）：`w:t` の文字、`w:tab` はタブ、`w:br` と `w:cr` は改行。`w:del`・`w:delText`・`w:instrText` は読まない（変更履歴は承諾した状態の文字になる）
  - 箇条書き：段落の番号付け（`w:numPr`）の段に応じて、字下げと「・」を付ける
  - 表（`w:tbl`）：`┌─ 表 ─`、行ごとに `│ セル │ セル`（セル内の段落は ` / ` でつなぐ）、`└─`
  - `w:sdt`・`w:customXml`・`w:ins`・`w:smartTag` は中身をたどる
- 続けて、脚注・文末脚注・コメントを「===== 脚注 =====」などの見出しのあとに付ける

### 7.3 xlsx
1. `xl/sharedStrings.xml` から共有文字列を読む（ふりがな `rPh` は除く）
2. `xl/styles.xml` の `cellXfs` から、日付の表示形式のスタイル番号を求める
   - 組み込みの書式番号：14–22、27–36、45–47、50–58
   - ユーザー定義の書式：引用符・角括弧・エスケープを除いたあとに y・m・d・h・s を含み、数値だけの書式でないもの
3. `xl/workbook.xml` と、その関連付け（rels）から、シート名とファイルを順に読む
4. 各行のセルを、列の番地に合わせて並べ、タブでつなぐ
   - 空のセルは空文字で埋め、末尾の空セルは除く
   - 型ごとの値：
     - `s`：共有文字列
     - `inlineStr`：セル内の文字
     - `b`：TRUE／FALSE
     - `str`・`e`：そのまま
     - 数値：日付のスタイルなら `YYYY/MM/DD`（時刻があれば `hh:mm` も付ける）
   - 数式があれば、値のあとに `‹=数式›` を付ける
   - セル内の改行は `↵` にする
5. シートの区切りに「===== シート: 名前 =====」を入れる

### 7.4 pptx
- `ppt/presentation.xml` のスライドの並び順に、各スライドの `a:p` の文字を1行ずつ取り出す
- 並び順が取れないときは、`slideN.xml` を番号順に読む
- スライドの関連付けからノートを探し、「〔ノート〕」のあとに付ける（数字だけの行は除く）
- スライドの区切りに「===== スライド N =====」を入れる

## 8. PDF（pdf.js）

### 8.1 起動と読み込み
- `lib()`：`pdfjsLib` の準備を待ち、埋め込んだワーカーの文字列から Blob URL を作って `workerSrc` に設定する（20秒で失敗とする）
  - あわせて、ワーカーの文字列の末尾の `export{… as WorkerMessageHandler}` を `self.pdfjsWorker = {…}` に置き換えた「通常のスクリプト」版の Blob URL を作る
  - 理由：file:// で開くとオリジンが `null` になり、pdf.js が自分でワーカーを起動しようとすると失敗して、メインスレッドで処理する「fake worker」になる（大きなPDFで画面が何秒も固まる）。モジュール形式のワーカーもオリジン `null` では起動できない
- `open(bytes)`：文書ごとに通常のスクリプト版でワーカーを起動し、`new PDFWorker({ port })` を `getDocument` の `worker` に渡す
  - 左右の文書の読み込み・描画が並行して進む
  - 文書の `destroy()` を包み、文書を閉じたらワーカーも終了させる。開くのに失敗したときも終了させる
  - ワーカーを起動できないときは、pdf.js に任せる
- `getDocument` のそのほかの設定
  - `data`：コピーしたバイト列
  - `CMapReaderFactory`：埋め込みの CMap を返す自前のもの
  - `cMapPacked: true`、`useWorkerFetch: false`、`isEvalSupported: false`、`useSystemFonts: true`
  - パスワードを求められたら入力欄を出す

### 8.2 文字の取り出し（`text(doc)`）
ページごとに `getTextContent()` の項目を順に処理する。
- 縦位置が文字の高さの0.6倍を超えて変わったら、行を改める
- 横の隙間が文字の高さの1.2倍を超えたら、空白を1つ入れる
- `hasEOL` の項目で行を改める
- 空の行は出力しない
- 各項目の文字は `normCJK` で正規化する
- ページの区切りに「===== ページ N =====」を入れる

読み込み側（main.js）は、区切り以外の文字が1つもないPDFを「文字情報なし（スキャン）」とする。

### 8.3 ページ（`pages(doc)`）
- 各ページの大きさ（倍率1の viewport の幅・高さ、単位 pt）を求める
- `draw(canvas, scale)`
  - 同じ canvas で描画中のものがあれば、取り消してから描く
  - 白で塗ってから描画し、取り消されたときは false を返す

## 10. テキスト比較（textview.js）

### 10.1 状態
| 項目 | 内容 |
|---|---|
| `rows`・`blocks` | 6.2 のとおり |
| `view` | 表示上の行。行番号（数）または省略行 `{fold, from, to}` |
| `rowToView` | 差分の行 → 表示上の行 |
| `uv`・`vToU` | 一列表示の行（`{v, k}`、k は `a`／`b`／`e`／`f`）と、表示上の行 → 一列表示の行 |
| `cur`・`hit` | 選択中の差分、検索で見つかった行 |
| `expanded` | 開いた省略行 |
| `undo`・`redo` | 元に戻す履歴（左右の行の配列の写し、最大200回分） |
| `unified`・`wrapDirty` | 一列表示か、折り返し表示を描き直す必要があるか |

### 10.2 比較（`compare(keepPos)`）
1. 比較の条件で各行を正規化する
   - 全角半角無視：NFKC
   - 大小文字無視：小文字にする
   - 空白をすべて無視：空白を除く
   - 空白の量を無視：連続する空白を1つにし、前後を除く
2. 正規化した文字列ごとに番号を振る
3. 空行無視が off のとき：`seq` と `buildRows` で比較する
4. 空行無視が on のとき（`diffIgnoringBlank`）：
   - 空行を除いた行で比較する
   - 結果に空行を戻す（左右とも空行の組は「一致」、片側だけなら「無視した差」）
   - 差分のまとまりを作り直す
5. 表示上の行を作る
   - 差分のみ表示のときは、差分の前後3行を残して一致部分を省略する
   - 省略が1行だけのときは省略しない
6. 行番号の欄の幅、横スクロールの幅（表示幅を、全角を2として数える）を求めて描く
   - 位置を保たないときは、最初の差分へ移動する

### 10.3 描画
- **仮想スクロール**：行の高さは固定（文字の大きさ 小・標準・大 で 18・20・24px）。見えている範囲の前後4行だけを HTML で描き、位置を `translateY` でずらす。左右の欄は縦横のスクロールを同期する
- **行の HTML**：

  ```
  <div class="row t-{種類} side{0|1} [pad] [cur first last] [hit]" data-v data-s>
    <span class="ln">行番号</span>
    <span class="tx"><span class="mk">−/+</span>本文</span>
  </div>
  ```
- **変更行の本文**（`inlineHtml`）
  - 変わった文字を `<span class="cd">` で囲む
  - 挿入位置に `<span class="ipt">` を置く
  - 右側には、数字の札 `<span class="dnum">` を置く
- **空白の記号表示**：半角空白・全角空白・タブを1回の置換で `<span class="wsc …">` にし、CSS の `::before` で `·` `□` `→` を重ねる。行末に改行の記号（↵＝CRLF、↓＝LF、←＝CR）を付ける。末尾に改行のない最終行には付けない
- **折り返し表示**
  - 縦の仮想スクロールをやめ、`#wrapView` にすべての行を描く
  - 左右表示では、1行を2列のグリッド（`.wrow`）にして、左右の行の高さをそろえる
  - 300行ごとのまとまりに `content-visibility: auto` を付け、画面外の描画を省く
  - 選択や検索が変わったときは描き直さず、`markWrap()` で該当行のクラスだけを付け替える
- **位置マップ**
  - 表示上の行の位置に、左の列は赤系、右の列は青系で差分を描く
  - 選択中の差分は、紫の帯で示す
  - 画面に見えている範囲を半透明の枠で描く
  - クリック・ドラッグで、その位置へスクロールする

### 10.4 操作
| 操作 | 処理 |
|---|---|
| 次・前の差分 | `cur` を1つ進める・戻す。未選択なら、画面の一番上より後の最初の差分へ。表示に入っていなければスクロールし、変更行は最初に変わった文字まで横スクロールする |
| 差分のコピー（`applyCopy`） | まとまりの左右の行番号の範囲（a0–a1 / b0–b1）で、コピー先の行の配列を作り直す。すべてのコピーは、後ろのまとまりから順に行う |
| 元に戻す | 変更の前に左右の行の配列の参照を履歴に積む（配列は変更せず作り直すので、参照の保存で済む） |
| 検索 | 正規化（NFKC＋小文字）した文字で、全行から一致する行を集める。現在位置の次の行へ移動し「n / m 件」を通知する。省略行の中なら開く |
| 一列表示 | 760px 未満では自動で切り替える（手動で選んだものを優先して覚える）。切り替え前に一番上に見えていた行を保つ |
| 行のダブルクリック | その行の位置で、テキストの編集画面を開く |

### 10.5 パッチ（`unified`）
- 比較条件を使わない、完全一致での比較結果から作る
- 前後3行の文脈を付ける。間が6行以下の差分は1つのハンクにまとめる
- 見出し：`diff --git a/名前 b/名前`、`--- a/名前`、`+++ b/名前`（名前は左のファイル名）
- 各行：
  - `-` と ` ` の行は左の改行コード、`+` の行は右の改行コードで終える
  - 末尾に改行のない最終行のあとには、`\ No newline at end of file` を置く
  - 一致行でも、片側だけ「改行のない最終行」にあたるとき（最終行が反対側では途中の行になる場合を含む）は、行末が違うので変更（`-` と `+`）として出力する。文脈行にすると `git apply` の結果が壊れるため
- 文字コード：左右とも Shift_JIS または EUC-JP（同じもの）ならその文字コード、それ以外は UTF-8 で書き出す

### 10.6 HTMLレポート
- 出力設定（`Report.options('text', …)`）：載せる行（画面と同じ／すべての行／差分と前後3行。省略した範囲は「n 行省略」）、並べ方（左右／一列：一致は1行、変更は変更前 − と変更後 ＋ の2行）、ファイル情報・比較条件と凡例の有無
- `meta` に CSP（`default-src 'none'; style-src 'unsafe-inline'`）を付ける
- 見出し：
  - 左右のファイル名・大きさ・更新日時・文字コード・改行
  - SHA-256（`crypto.subtle` で計算）
  - 未保存の編集があればその注記
  - 作成日時、差分の件数、比較条件、凡例
- 本文：表示上の行（省略を含む）の表
  - 行番号の欄に ＊・−・＋ の記号
  - 左は取り消し線、右は下線
- 印刷：`print-color-adjust: exact` で色を残す。見出し行は各ページに繰り返す

## 11. ページ表示・注釈（pageview.js）

### 11.1 注釈のデータ
ページ番号（0始まりの文字列）ごとの配列で持つ。

| 種類 `t` | 項目 |
|---|---|
| `pen` / `marker` | `c` 色、`w` 線の太さ、`p` 点の配列 `[[x, y], …]` |
| `rect` | `c` 色、`lw` 線の太さ、`x`, `y`, `w`, `h` |
| `note` | `x`, `y`, `text` 文字、`bg` 背景色 |
| ※ `stamp`（日付印）は v1.2.0 で廃止。古い注釈ファイル・保存データにあっても、検証で捨てる |

座標はページの座標系（pt、回転前）で持つ。

### 11.2 検証（`cleanAnnot` / `cleanAnnMap`）
保存領域から読むとき、注釈ファイルを読み込むとき、描画する直前に、必ず通す。

- 色：`#` に続く16進3〜8桁だけを通す。それ以外は既定の色にする
- 座標・大きさ：有限の数値で、±100000 に収まるものだけを通す
  - 線の太さ：0.2〜40
  - 印の半径：12〜60
- 文字：文字列だけを通す。付箋は2000字まで、印の各欄は40字まで
- 点の数は20000まで、1ページの注釈は5000件まで
- ページ番号は5桁までの数字だけを通す
- 注釈ファイルの `side` は 0 か 1、回転は 0/90/180/270 だけを通す
- 種類が分からないもの、必要な項目がないものは捨てる

### 11.3 描画
- 各ページの上に、viewBox をページの大きさにした SVG を重ね、注釈を SVG の要素として描く
- 細い線は、透明で太い当たり判定の線を重ねて、選びやすくする
- 蛍光マーカーは、`mix-blend-mode: multiply` で下の文字を隠さない
- 付箋の大きさは文字数から求める（全角を1文字分、半角を0.58文字分）
- 付箋は、置くときにページの内側に収まるよう位置を補正する

### 11.4 ページの表示
- **拡大率**（css px / pt）
  - 幅に合わせる：(列の幅 − 36) ÷ 最大のページ幅
  - ページ全体：幅と高さで小さい方
  - 指定：倍率 × 96 / 72
  - ＋／−ボタンは 25・33・50・67・75・100・125・150・200・250・300・400% の順に切り替える
- **回転**：ページの要素に CSS の `rotate` をかける。外枠は縦横を入れ替えた大きさにする。注釈の層も一緒に回るので、マウスの位置は `getScreenCTM().inverse()` でページの座標に戻す
- **遅延描画**
  - IntersectionObserver（前後 600px）で、見えてきたページだけを描く
  - 見えなくなったページは canvas を空にする
  - 1ページの画素数は 4096² までに制限する
  - 描画中に倍率が変わったら、描き終えてからもう一度描く
- **スクロールの連動**
  - スクロールした側のページ番号と、ページ内の位置の割合を求め、反対側の対応するページ（`PageMatch.other`。対応付けがなければ同じページ番号）の同じ割合へ合わせる
  - 連動で動かした側には、実際に設定された位置（端では切り詰められる）を `expect` に覚えておき、その位置の scroll イベントだけを無視する（連動の往復を防ぐ）。位置が変わらなかったときはイベントが来ないので覚えない
  - v1.2.0 より前は「動かした側を0.15秒固定」していたため、その間に反対側を動かすと連動せず、左右がずれることがあった
- **狭い画面**（760px 未満）：「左右に並べる」を片側だけの表示に切り替える

### 11.5 操作
| ツール | 押したとき | ドラッグ | 離したとき |
|---|---|---|---|
| 選択 | 注釈の上なら選んで移動を始める。なければ画面を動かす | 移動・画面のスクロール | 保存 |
| ペン・マーカー | 点を始める | 0.7pt 以上動いたら点を足す | 1点だけなら小さな点にして保存 |
| 枠 | 始点 | 四角を広げる | 2pt 未満なら捨てる |
| 付箋 | クリックした位置に入力欄（`inlineNote`）を出し、貼ったら選択ツールに戻す | — | — |
| 消しゴム | 押した注釈を消す | — | — |

- キー操作：Delete・Backspace で選んだ注釈を消す。Esc で選択ツールに戻す。Ctrl+Z／Ctrl+Y（Ctrl+Shift+Z）で取り消し・やり直し
- 付箋の編集：選択ツールで同じ付箋を 450ms 以内に2回押すと、その場に入力欄を出す（ドラッグのためにポインタを捕まえると click・dblclick が届かないため、押した間隔で判定する）
- 取り消し：変更の前の注釈（その側の全ページ）を JSON の文字列で `undo` に積む（最大200）。移動・描画は、離したときに変わっていれば積む
- 色：道具ごとに覚える（`pv:toolColor`。既定 ペン 赤・マーカー 黄・枠 青・付箋 黄）。付箋の背景は選んだ色の淡い色
- 付箋：文字の大きさ `fs` ＝ clamp(11, ページ幅 ÷ 54, 60) pt を注釈に記録する。幅は全角20文字（`fs` × 20）で折り返す
- マーカーの太さは線の太さの5倍（「中」で 10pt）

### 11.5.1 変更箇所の表示とコメント
- 「変更箇所」（`pvChanges`、既定オン、`doccmp:pvChanges` に覚える）：左右とも読み込んでいるとき、見えているページについて、対応するページの組（`PageMatch.ready()`、なければ同じページ番号）の変更箇所を `OV.regionsFor(l, r)` で求め、ページごとの SVG（`.pv-chg`）に点線の枠と番号の札を描く
- `regionsFor`：一括チェックと同じ `analyzePair`（描画の幅・位置合わせ・感度・許容）で比べ、枠を各ページの pt に直す関数 `toPt(side, 枠)` を返す。右は位置合わせ（回転→平行移動）を逆にたどる。ファイル・感度・許容・解像度ごとに覚える
- 札の文字は画面上で 12px になるよう、拡大率で割った大きさにする。枠の色は状態（確認済＝緑、要確認＝赤橙、未確認＝橙）。コメントがあれば札にその先頭（40文字）を出す
- 札のクリックで、その位置にコメントの入力欄（`#pvNotePop`）を出す。札以外はクリックを通す（下の注釈の操作を妨げない）

### 11.7 レポート
- 出力設定（`Report.options('page', …)`）：並べ方（左右とも読み込んでいるとき：`side` 左右の対応するページを並べる（既定）／`single` 1ページずつ）、画質、ファイル情報・注釈の一覧表・各ページの付箋の有無
- 載せるページ：注釈のあるページだけ／すべて。左右に並べるときは、左右の組（`PageMatch.ready()`、なければ同じページ番号どうし）のどちらかに注釈があれば載せる
- 各ページを `renderWithAnn`（印刷と同じ、注釈込み）で描き、JPEG（品質 0.82）の data URL にして埋め込む
- 注釈の数（種類ごと）と付箋の内容の一覧を付ける。文字はすべてエスケープする

### 11.6 保存
- 識別キー：`名前|大きさ|更新日時`
- `persist` が on のとき：`doccmp:ann:キー`・`doccmp:rot:キー` に保存する（注釈が空なら消す）。v1.5.0 から `persist` の既定はオフ
- 注釈ファイル（version 2）：`{app, version, savedAt, author, files:[{side, name, size, sha256, rot, annotations}], notes}`。読み込むときは形式を確かめ、`notes` は今の左右の組のコメントに足す
- 常にメモリ（`mem`）にも持ち、`persist` が off のときはメモリだけを使う

### 11.7 印刷
1. 対象（左のみ・右のみ・両方）を選ぶ
2. 各ページを倍率 min(2.5, 2400 ÷ 長辺) で描く
3. 注釈を、SVG を data URL の画像にして重ねる
4. 回転をかけて JPEG（品質0.92）にする
5. `#printArea` に並べ、`window.print()` を呼ぶ
6. `afterprint` で後片付けをする

印刷用の CSS では、`#printArea` 以外を隠し、用紙の余白を0にする。

## 12. 重ね合わせ比較（overlay.js）

### 12.1 状態と定数
| 項目 | 内容 |
|---|---|
| 描画の幅 W | clamp(900, 上限, 左右の大きい方のページ幅 × 2)。上限は設定 `ovRes`：軽量 1600／標準 2400／精細 4000px。左右とも同じ W の幅で描く |
| 倍率 `resF` | W ÷（標準で描いた場合の W）。A4 などの小さなページは上限に届かないので、どの設定でも 1。許容幅・ます目・最小の画素数をこの倍率で換算する |
| 描画の保持 | 12件まで、かつ合計 6000万画素まで（古いものから参照を外す。全ページ表示で表示中のページが使っていることがあるので、canvas の大きさは0にしない。表示から外れたページの canvas とともに GC で解放される） |
| 位置合わせ | `align`：`"左ページ:右ページ"` → `[dx, dy, 角度]`。ファイルが変わったら消す |
| スキャンの判定 | 左右のどちらかが画像、または文字情報のないPDF |
| ずれの許容 | 0〜5（標準での px。実際の半径は round(値 × resF)、最低1）。ファイルが変わったら、スキャンなら2、それ以外は0にする |
| 世代番号 `gen` | 描画のたびに進める。解像度の変更・ファイルの変更でも進め、実行中の描画・位置合わせ・一括チェックの結果を捨てる |
| 差分の感度（閾値） | 5〜160、既定60（明るさの差） |

### 12.2 差分の計算（`diffImage`）
1. 右の画像を「中心で回転 → (dx, dy) だけ移動」して描き、左右を同じ大きさの明るさの配列にする
   - 明るさ ＝ (77R + 150G + 29B) / 256
   - 位置合わせ量と倍率は引数 `{dx, dy, ang, resF}` で受け取る（途中で制御を返すため、共有の状態を読まない）
2. （欠番：v1.1.2 で白黒への二値化をやめた）
3. 許容量 r > 0 のとき、3×3 の最小値フィルタを r 回かけた画像（濃い部分を太らせたもの）を作る
4. 各画素を判定する
   - スキャン かつ 許容量 > 0 のとき（2段階のしきい値）：STRONG ＝ 170、WEAK ＝ min(250, 170 ＋ 閾値)
     - 左の明るさ < STRONG かつ 右の太らせた明るさ ≥ WEAK → 左だけ
     - 右の明るさ < STRONG かつ 左の太らせた明るさ ≥ WEAK → 右だけ
     - 縮小や回転で細い線が薄くなっても（STRONG と WEAK の間）、消えたとは判定しない
   - それ以外：
     - 左の明るさ ＋ 閾値 < 右の太らせた明るさ → 左だけ（赤 229,50,45）
     - 右の明るさ ＋ 閾値 < 左の太らせた明るさ → 右だけ（青 26,115,232）
   - 色の変化（「色の違いも検出」がオンのとき）→ 紫（156,54,181）、mask ＝ 3。条件：左右とも白（明るさ 235 超）でない画素のうち、どちらかの彩度（RGB の最大−最小）が 40 以上で、重み付きの色の距離（2ΔR²＋4ΔG²＋3ΔB²）が (max(40, 閾値))² × 9 を超えるもの。ずれの許容が 1 以上なら、相手の許容の半径の中に近い色があるとき（両方向）は除く。最後に、上下左右も色が変わっている画素だけを残す（縁のにじみを除く）。既定は、左右どちらかが文字のないPDF（紙のスキャン）ならオフ、それ以外はオン
   - それ以外 → 共通。「共通部分を薄く」なら 255 − (255 − 暗い方) × 0.32
5. 変わった画素を max(8, round(16 × resF)) px 四方のます目で数える
   - max(2, round(3 × resF)) 画素以上のます目を「変わったます目」とする
   - 前後左右2ます以内でつながるものをまとめる
   - まとまりの合計が max(4, round(8 × resF)) 画素未満なら捨てる
   - まとまりを6pxの余白付きの枠にする
6. 枠を上から（縦の差が30px未満なら左から）並べて番号を振る
7. 変化量 ＝ 変わった画素数 ÷ 文字・図の画素数（どちらかの明るさが200未満の画素）
8. 段階の間と、400行ごとに `await sleep(0)` で画面に制御を返す。差分画像は、表示を消す前に計算する

### 12.3 自動位置合わせ（`autoAlign`）
評価値 ＝ どちらかが濃い画素についての、濃さの差の平均（小さいほど一致）。縮小の描画には `imageSmoothingQuality: 'high'` を使う。

| 段階 | 縮小 | 回転 | 平行移動 | 画素の間引き |
|---|---|---|---|---|
| 1 | 1/f1（f1 ＝ max(4, round(W / 600))） | 0° | ±ceil(56 × max(1, W / 2400) ÷ f1) | なし |
| 2 | 1/f2（f2 ＝ max(3, round(W / 800))） | −1.2〜1.2°（0.1°刻み） | 段階1の結果の周り ±3 | 2 |
| 3 | 1/f2 | 段階2の結果の ±0.06°（0.02°刻み） | ±1 | 2 |
| 4 | 原寸 | 固定 | ±3 | 3 |

- 粗い段階は、描画の幅によらず幅 600〜800px 程度に縮小して探す（精細でも遅くならないように）。探す範囲は「標準で ±56px」に相当する実寸
- 角度ごと・平行移動の1行ごとに `await sleep(0)` で画面に制御を返す。初回の自動位置合わせは処理中の表示を出す

戻り値は `[dx, dy, 角度]`。0.01°未満の角度は0にする。

### 12.4.1 表示の大きさと操作
| 項目 | 内容 |

| 縦に合わせる（`fith`） | 表示領域の高さ − 30px に合わせた幅 |

| 表示領域の大きさの変化 | ResizeObserver で表示領域を見張り、幅・高さが変わったら「幅に合わせる」「縦に合わせる」の大きさを合わせ直す（ファイル欄の開閉・タブを開いた直後・全画面など）。表示領域の幅が 0（見えていない）のときは大きさを決めない（開いた直後に最小の 200px で描かれ、そのまま残る不具合の対策）。ページ表示も同様に、左右の表示領域の幅が変わったら合わせ直す |

| ホイール | 通常：ホイール＝縦スクロール、Shift＋ホイール＝横スクロール（ブラウザの標準）。Ctrl（Mac は ⌘）＋ホイール＝拡大・縮小（`passive: false` で `preventDefault` し、ブラウザの拡大より優先）。倍率は exp(−deltaY × 0.0015) |
| 手のひらツール | ボタンまたは H で切り替え。ドラッグで表示位置を動かし、ホイールで拡大・縮小する。中ボタンのドラッグは、手のひらツールでなくても表示位置を動かす |
| ページ送り | PageUp／PageDown は、文字入力欄（textarea、text・number・search の input）以外にフォーカスがあれば効く。←／→ は入力欄・選択欄以外で効く |

### 12.4.2 1ページ表示と全ページ表示
描画は2段に分ける：`prepare(pl, pr, l, r, gen)`（描画・位置合わせ・差分の計算。世代番号が変わったら null）と、`compose(d)`（表示用の要素を組み立てる）。`compose` の結果 `v` は、そのページの表示要素・変更箇所・選んだ枠の番号・並べて表示の canvas・点滅の描画関数（`frame(on)`）・スワイプの描画関数を持つ。今のページの `v` を `st.cur` とし、右のパネル（結果・位置合わせ・前後の変更・自動位置合わせ）はこれを対象にする（`setCurrent`）。

| 項目 | 1ページ表示 | 全ページ表示 |
|---|---|---|
| 組み立て | 今の組だけを `prepare`→`compose` して表示する | 組の一覧（12.6、片側だけなら各ページ）を作り、ページごとに見出し（「左 n ／ 右 m」、追加・削除・変更箇所の数の札）と、ページの大きさの仮の枠（`.ov-ph`、描画の画素数 `data-w`・`data-h`・`data-scale` を持つ）を並べる |
| 描くページ | 今の組 | IntersectionObserver（表示領域の上下 120%）で近くにあるページを調べ、今のページに近い順に1つずつ描く（`pump`）。遠ざかったページは仮の枠に戻し、描画を捨てる（`releaseSlot`） |
| 今のページ | 選んだ組 | 表示領域の上から 1/3（最大 200px）の位置にあるページ。スクロールのたびに決め直し、ページ番号の欄と右のパネルを合わせる |
| ページ送り | 組を変えて描き直す | そのページの見出しまでスクロールする（`go`、`scrollToSlot`） |
| 表示の位置の保持 | — | 表示方法・感度などを変えて組み立て直すときは、今のページとその中の位置を覚えて戻す。上にあるページの描画で高さが変わっても、見ている位置がずれないようにスクロールを補正する |
| 位置合わせの変更 | 描き直す | 今のページだけ描き直す（`redrawSlot`） |
| 点滅・スワイプ | 今のページ | 点滅の切り替え（タイマー・クリック・Space）とスワイプの境界は、描いてあるすべてのページに反映する |
| 拡大・縮小 | canvas の大きさを変える | canvas と仮の枠の大きさを変える。カーソルの位置にあるページを基準にスクロール位置を補正する |

- ファイルを読み込み直したら、組の一覧を捨てて先頭のページから表示する
- ページの対応付けが後から終わったときは、組の一覧を作り直す

### 12.5 全ページ一括チェック
- ページの組（12.6。対応付けがオフなら同じページ番号どうし）を、1ページ表示と同じ W と位置合わせ（スキャンならページごとに自動で推定して覚える）で比べる（`analyzePair`）
- 各組の変更箇所の数と変化量を一覧にする。片側にしかないページは「追加」「削除」とする。行を押すとその組を開く
- 途中で中止できる

### 12.6 ページの対応付け（pagematch.js）
- **特徴**
  - 文字のあるPDF：抽出文字を「===== ページ N =====」で分け、ページごとに「行の集まり」（空白を詰めて NFKC 正規化）と「2文字の組」を作る。文字がほとんどない（2文字の組が20未満）ページが半分を超えるときは、見た目で比べる
  - スキャン（`noTextLayer`・画像）：ページを長辺 160px で描き、48×66 に縮小した濃さ（255 − 明るさ）。左右のページ数が同じなら1対1とみなし、縮小画像は作らない
- **似ている度合い**
  - 文字：両方とも3行以上なら行の Dice 係数、そうでなければ2文字の組の Dice 係数。しきい値 T ＝ 0.3
  - 見た目：コサイン類似度（両方ほぼ白紙なら 1、片方だけなら 0）。しきい値 T ＝ 0.55
- **並び**：動的計画法。組にする（度合い − T > 0 のときだけ、その値を加える）、左だけ、右だけ の3通りで、合計が最大になる並びを選ぶ。対角線から |n − m| ＋ 30 を超えて離れた組は調べない
- **後処理**：組にならなかった左右のページが同じ数だけ続く区間は、順に組にする（内容が大きく変わったページ）
- **結果**：`{l, r}` の配列（片側にしかないページは反対側が -1）。左右のファイルの識別キーと行数から作ったキーで覚え、ファイルが変わったら捨てる
- **使う場所**
  - 重ね合わせ：連動中で対応付けを計算している途中にページ送り・ページ番号の選択が来たら、計算が終わるのを待ってから行う（待っている間に複数の操作が来たら最後の1つだけ）。計算が終わったら、今の左のページに対応する右のページへ直す（途中で描き直していても）
  - 重ね合わせ：連動中のページ送りは組の順に進む（片側にしかないページは片側だけを表示し、「右だけにあるページです」などと示す）。ページ番号の選択でも反対側を対応するページに合わせる
  - 一括チェック・レポート：組ごとに比べる
  - ページ表示：スクロールの連動で反対側のページを決める（`other`。対応がないページは直前の対応から推定）
- 重ね合わせのタブを開いたとき・ファイルが変わったとき（タブを開いていれば）に計算し、右側のパネルに「右で追加されたページ：3」などと示す

### 12.7 レポート
- 出力設定（`Report.options('overlay', …)`）：画像の並べ方（`diff` 差分画像／`side` 左右に並べる／`both` 両方）、画質、ファイル情報・比較条件・ページの一覧・変更箇所の位置の表の有無
- 載せる画像：変更のあるページだけ／すべて（追加・削除されたページはどちらでも載せる）。変更のないページは一覧にだけ載せる
- 組ごとに `analyzePair` で比べ、差分画像に枠と番号を描いて、画質の幅（軽量 900／標準 1400／高精細 2200px）までの JPEG（品質 0.82）の data URL にする
- 左右に並べる（`sideImages`）：左はそのまま、右は位置合わせした状態で同じ大きさに描き、`mask` の画素を左は赤・右は青にして、枠と番号を両方に描く。幅は画質の幅の 0.7 倍。追加・削除されたページは、ない側に「対応するページなし」の枠を置く
- 変更箇所ごとに、位置（ページの左上からの割合）と大きさ（ページに対する割合）の表を付ける
- 比較条件（感度・許容・解像度・ページの対応付け）、ファイル情報（SHA-256）を載せる

## 13. フォルダ比較（folder.js）
- **フォルダの受け取り**
  - フォルダ選択（`webkitdirectory`）：相対パスの先頭（フォルダ名）を除く
  - ドロップ：`webkitGetAsEntry` でたどる（`readEntries` を空になるまで繰り返す）
- **内容の比較**：4MB ずつ読み、4バイト単位（端数は1バイト単位）で比べる
- **一覧**
  - 状態（同一・相違・左のみ・右のみ・比較中）で絞り込む
  - 列の見出しで並べ替える（状態は 相違 → 左のみ → 右のみ → 比較中 → 同一 の順）
  - 25件ごとに描き直して、進み具合を表示する
  - 比較中に左右のフォルダが変わったら、世代番号 `gen` で前の比較を打ち切り、最初からやり直す
- **選択と開く**
  - クリックは選んだ行のクラスだけを付け替える（表を描き直すとダブルクリックが成立しないため）
  - ダブルクリック・Enter で、`App.loadPair` を呼ぶ。読み込んだら、各画面に変更を知らせてからファイル比較のモードに移し、「← フォルダ一覧」を出す（先にモードを変えると、テキスト比較が古い比較結果を新しい文書で描こうとして失敗する）
- **CSV**：ファイル・状態・左右のサイズ・左右の更新日時。BOM 付き UTF-8、CRLF、全項目をダブルクォートで囲む
- **レポート**：件数の集計と一覧（相違 → 左のみ → 右のみ → 比較中 → 同一 の順）

## 13.2 ヘッダ・ファイル欄・全画面・ドロップ先（main.js）
- **ヘッダ（1行）**：比較の種類（`#modeSw`）、タブ、左右のファイル名（`#hdrFiles .hf`。空ならクリックでファイル選択、読み込み済みならファイル欄の開閉）、▾（`#btnSlots`）、「← フォルダ一覧」、全画面、すべて閉じる、設定、ヘルプ
- **モード**（`App.mode`：`file`／`folder`）：`body[data-mode]` に反映し、フォルダ比較ではタブ・ファイル名・ファイル欄を CSS で隠す。`setTab('folder')` は互換のため `setMode('folder')` として扱う
- **ファイル欄の開閉**：`body.slots-closed`。左右が「両方そろった」ときに自動でたたみ、どちらかが空になったら開く（利用者が開いたものは、次に両方そろい直すまで閉じない）
- **全画面**：「全画面を終える」（`#btnExitFull`）は、今のタブ（フォルダ比較ではフォルダ比較）のツールバーの右端に移して並べる（`placeExitFull`。タブ・モードを切り替えるたびに移す）。画面の右上に浮かせると、ツールバーの右端のボタンに重なるため。`body.fullview` でヘッダとファイル欄を隠し、`requestFullscreen` でブラウザも全画面にする。ブラウザの全画面が Esc で終わったら（`fullscreenchange`）ヘッダも戻す。ブラウザの全画面が使えないときも Esc で戻る
- **ドロップ先**：`dragenter`／`dragover` で、カーソルが画面の左半分か右半分かで `.dz[data-side]` を強調する。`dataTransfer.items` が2つ以上なら「左右に読み込む」だけを出す。ドロップした位置の側に読み込む（フォルダならフォルダ比較のその側）
- **ヘッダのファイル名**（`fitHdrNames`）：左右とも全体を入れて割り当てられた幅を測り、はみ出す側だけを縮める（片側ずつ縮めると、もう片側の幅が変わるため2段階で行う）。左右の名前の共通の先頭が6文字以上なら「…」にして違う部分から出す（英数字の途中なら、その語の頭まで戻す）。入らなければ「…違う部分の頭…拡張子」、さらに狭ければ拡張子を省く。共通部分がなければ、先頭4割・末尾6割を残して真ん中を「…」にする。幅は canvas の measureText で測る。読み込み・モードの切り替え・「フォルダ一覧」の表示・画面の大きさの変更で測り直す
- **混み合う幅**：1600px 未満で右側の操作ボタン、1240px 未満で比較の種類とブランド名、1100px 未満で選んでいないタブと「フォルダ一覧」をアイコンだけにする（名前は title と読み上げに残る）
- **比較条件のポップアップ**：`details.pop`。外側のクリック・Esc で閉じる。既定から変えている条件の数をボタンに出す

## 14. アプリ本体（main.js）

### 14.1 形式の判定（`sniff`）
| 先頭のバイト | 判定 |
|---|---|
| `25 50 44 46`（%PDF） | pdf |
| `89 50 4E 47` | image/png |
| `FF D8 FF` | image/jpeg |
| `47 49 46 38` | image/gif |
| `42 4D`（27バイト以上） | image/bmp |
| `52 49 46 46 …. 57 45 42 50` | image/webp |
| `49 49 2A` / `4D 4D .. 2A` | tiff（未対応の案内） |
| `50 4B 03 04` | zip（Office の判定へ） |
| `D0 CF 11 E0` | ole（旧Office の案内） |

### 14.2 読み込み（`prepare`）
- pdf：開く → 文字を取り出す（進み具合を表示）→ 文字情報の有無を判定 → ページは必要になったときに作る
- 画像：比較用の文字は空にし、ページを作る
- Office：文字を取り出し、ページは文字から作る
- その他：
  - 文字コードを判定する。英数字だけなら、その印を付ける
  - .xdw・旧Office・TIFF は、案内を出したうえでバイナリまたはテキストとして読む

### 14.3 文書が変わったとき（`changed`）
1. 元に戻す履歴を消す
2. ファイル欄を描き直す
3. 各画面の `invalidate` を呼ぶ
4. 左右の両方があり、どちらかが文字情報のない画像・スキャンで、両方が PDF か画像のときは、テキスト比較から重ね合わせ比較へ切り替えて通知する（`autoTab`）

### 14.4 編集と変更の有無
- 編集画面の初期値は、行を改行でつなぎ、末尾の改行があればそれも付ける（付けないと、適用しただけで末尾の改行が消えるため）
- 適用したとき、入力欄が改行で終わっていれば「末尾の改行あり」とする
- 変更の有無（`dirty`）は、行の内容と末尾の改行の有無を合わせたもの（`textSig`）を、読み込み時・保存時の値と比べて決める
- 元に戻す履歴には、左右の行の配列と末尾の改行の有無を保存する
- 保存していない変更がある側を、ファイルの読み込み（ドロップ・ファイル選択・フォルダ比較からの表示）で置き換えるときは、「保存していない変更」の確認を出す（`confirmDiscard`）

### 14.5 テキスト比較の状態表示
- 差分が0件でも、左右のバイト列が違い、どちらかがバイナリのときは「⚠ バイナリの内容が異なります」と、最初に違う位置（オフセット）を表示する（バイナリは先頭 4MB だけを表示・比較するため）
- 差分があり、どちらかが 4MB を超えるバイナリのときは、それより後ろの違いは数に含まないことを添える

### 14.6 保存（`saveSide`）の確認
1. PDF・Office：「取り出した文字だけを UTF-8 のテキストとして保存する」ことを確認する
2. 英数字だけのファイルに日本語が入ったとき：保存する文字コード（UTF-8／Shift_JIS）を選ぶ
3. 改行が混在していたとき：統一して保存してよいかを確認する（1回だけ）
4. 表せない文字があるとき：そのまま（? に置換）か、UTF-8 で保存するかを選ぶ
5. `showSaveFilePicker` があれば保存ダイアログ、なければダウンロードにする

## 16. 既知の制限
- Word・Excel・PowerPoint のページ表示は、取り出した文字を A4 に組んだ簡易表示で、元の見た目ではない
- PDF の文字の取り出しは見た目の行ごとのため、語句の挿入で折り返しが変わると、以降の行も差分になる（段落単位の比較は2回目で対応予定）
- 自動位置合わせが補正するのは、平行移動と ±1.2° の回転だけ。拡大縮小は補正しない
- 同じ値の数字の書式の違い（1,000 と 1000）は差分になる
- ZIP64 形式の Office 文書は読めない
