## 1. はじめに

### 1.1 目的
本書は文書比較ツール「ShibaDiff」が満たすべき要件を定める。開発・評価・改修の判断基準とする。

### 1.2 対象範囲
- ShibaDiff 本体（単一HTMLファイル）の機能・品質に関する要件
- ビルド・テストの仕組みは、開発を支えるものとして要件の範囲に含める
- 対象外：ファイルの変換ツール（DocuWorks→PDF など）、OCR、サーバー側のしくみ

### 1.3 要件の状態の表記
| 表記 | 意味 |
|---|---|
| 済 | v1.5.14 までに実装済み |
| 2回目 | 次の開発で実装する（採用済み） |
| 3回目 | その次の開発で実装する（採用済み） |
| 保留 | 採否を保留中 |
| 見送り | 実装しない |

## 2. 背景と目的

### 2.1 背景
社内の文書確認業務では、次の2種類のツールを使い分けている。
- **WinMerge**：テキストの差分を確認する
- **DocuWorks Viewer**：文書をページのまま並べて見比べ、付箋などの注釈を付ける

このため、次のような問題がある。
- PDF・Word・Excel の版の違いを確かめるために、テキストへの変換などの手間がかかる
- スキャンした文書や図面の変更箇所は、目視で探すしかない
- ツールのインストールに管理者権限が必要な端末や、外部ネットワークに出られない端末がある

### 2.2 目的
1. テキスト・Office文書・PDF・画像の版の違いを、1つのツールで漏れなく確認できるようにする
2. 確認結果に注釈を付け、印刷・PDF・レポートとして残せるようにする
3. インストール不要・ネットワーク不要で、閉じた社内環境でも安全に使えるようにする

### 2.3 達成の目安
- 20人の業務別レビューで、用意した正解の差分を全員が「漏れなし」と確認できること（v1.0 で達成）
- 全レビュアーが「業務で使いたい」と答えること（v1.0：全員が条件付きで「はい」、平均★3.2／5）

## 3. 利用者と利用場面

### 3.1 利用者
| 区分 | 主な利用者 | 主に使う機能 |
|---|---|---|
| 文書管理・審査系 | 法務、総務（規程管理）、品質保証、自治体の文書管理、薬事 | Word・PDFのテキスト比較、新旧対照、注釈、印刷 |
| 数値・表計算系 | 経理、購買、人事、経営企画 | Excel・CSVの比較、数値の差 |
| 図面・画像系 | 機械設計、施工管理 | 重ね合わせ比較、位置合わせ、スキャン図面 |
| 技術系 | ソフトウェア開発、社内SE、テスト | ソースコード・設定ファイル・ログの比較、パッチ、フォルダ比較 |
| 一般 | 営業、一般事務、テクニカルライター、研究 | 提案書・申請書・マニュアル・論文の版の確認 |

### 3.2 代表的な業務の流れ
```
受け取った修正版を開く
  → 旧版と左右に並べて比較（テキスト／ページ／重ね合わせ）
  → 変更点を1つずつ確認（前へ・次へ）
  → 必要に応じて付箋・枠などの注釈を付ける
  → 印刷・PDF・レポートで記録を残す／上長に回す
```

| FR-IN-19 | ファイルを閉じる（×・すべて閉じる）と、その文書に付けた注釈・コメントのうち保存していないものは消えるので、あるときは閉じる前に確認を出すこと。パスワードの入力欄には、どのファイルのパスワードかを示すこと | 済 |

| FR-TX-14 | テキストを編集して比較し直せること | 済 |

| FR-TX-16 | 保存するときは、元の文字コード・改行コード・BOM・末尾の改行の有無を保つこと。表せない文字があるとき、英数字だけのファイルに日本語を入れたとき、改行が混在していたときは確認を出すこと | 済 |
| FR-TX-17 | 文字コード・改行コード・末尾の改行だけが違うときは、その旨を表示すること | 済 |
| FR-TX-26 | 末尾の改行の有無が左右で違うときは、ほかに差分があっても状態表示・比較欄（改行のない側の最終行に「改行なし」の札）・変更点一覧・レポートに示すこと。行の差分ではないので差分の件数には数えないこと | 済 |
| FR-TX-27 | Word 文書に変更履歴（挿入・削除・移動）が残っているときは、読み込み時に件数を通知し、ファイル欄と状態表示にも示すこと。比較は、変更をすべて承諾した状態の文字で行うこと（内容の一覧は FR-TX-24） | 済 |
| FR-TX-28 | 差分のまとまりの中では、似ている行どうしを左右に並べること（長い行が「ほぼ同じ」であることを、短い見出しの一致より優先する）。空行や短い見出しのような同じ行をはさんで変更が続くときは、まとめて対応を求めること。行の削除と番号の繰り上げ（請求項・条文・表の行・アクセスリスト）があっても、別の行どうしを「変更」として並べないこと | 済 |

| FR-TX-33 | 行頭の印（− ＋）には、読み上げ用に意味（変更前・変更後・左のみ・右のみ）を付けること。変わった文字は、削除・挿入を表す要素（del・ins）にすること。取り消し線は、重なった文字（半角カナの長音など）が読める細さ・濃さにすること | 済 |
| FR-TX-18 | 文字情報のない画像やスキャンPDFでは「同一」と表示せず、警告を出して重ね合わせ比較へ案内すること | 済 |
| FR-TX-19 | PDFの折り返しをつないで、段落単位で比較できること（切り替え可） | 2回目 |

## 6. 制約事項・前提
- DocuWorks 文書（.xdw）は仕様が公開されていないため読み込めない。DocuWorks で PDF に変換して使う
- スキャン画像の文字は読み取らない（OCR なし）。スキャン文書は重ね合わせ比較で確認する
- Word・PowerPoint のページ表示は文字だけの簡易表示であり、元の見た目とは異なる（PowerPoint は3回目で画像表示に対応予定）
- ブラウザの制約で、選んだフォルダへの書き込みや、元のファイルへの上書きはしない
- 注釈はブラウザごとに保存される。別のPCへ移すときは注釈ファイルを書き出して使う

## 7. 用語集
| 用語 | 意味 |
|---|---|
| 差分（のまとまり） | 連続して変わっている行のかたまり。「差分 n 箇所」はこのかたまりの数 |
| 変更／左のみ／右のみ | 左右両方にあって内容が違う行／左にだけある行（削除）／右にだけある行（追加） |
| 行内差分 | 変更行の中で、実際に変わった文字や単語 |
| 一列表示 | 左右に並べず、変更前と変更後の行を1列に並べる表示（git diff に近い） |
| 重ね合わせ比較 | ページを画像として重ね、画素の違いから変更箇所を見つける比較 |
| ずれの許容 | 重ね合わせ比較で、何ピクセルまでのずれを差分としないか |
| パッチ | 差分を `git apply` などで適用できる形式（unified diff）にしたテキスト |
| 康熙部首 | 「⽉」「⽇」など、通常の漢字と見た目は同じだが別の文字コードの文字。PDF から文字を取り出すと混ざることがある |
| CSP | Content-Security-Policy。ブラウザに、通信や外部の読み込みを禁止させる仕組み |
